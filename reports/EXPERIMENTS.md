# Experiment log: Deliverable 1 (photo vs. other)

Chronological record of **everything** done for the photo classifier: experiments, results, incidents,
deletions and decisions. It's meant for studying how the model was optimized and what can still be improved.

**Companion files (versioned):**

| File | Content |
|---|---|
| `reports/experiments_d1.csv` | one row per training run: all settings, metrics, verdict, lesson (generated by `leyenda.tracking.export_runs_csv`) |
| `reports/journal_d1_classifier*.md` | hypothesis → result → verdict → lesson for each run (generated by `training_journal`) |
| `reports/d1_v1_error_analysis.csv` | every validation error of model V1, with its cause group (A–F, see §9) |
| `notebooks/01_classification.ipynb` | the deliverable: all code, curves, analyses |

**Not versioned (too large, regenerated by code):** `data/` (images), `runs/` (models, checkpoints, per-epoch logs),
`models/`, `reports/figures/`.

**Rules (since 2026-10-09):** runs are never deleted. An interrupted or failed attempt is kept and marked
`aborted` with its reason. Every step is committed on branch `Simon` with a detailed message.

## 3. Part 1 experiments (2026-10-05)

All on the first-delivery split. Validation metrics; "gap" = train acc − val acc.

| Run | Model / change | Train acc | Val acc | Val F1 | Val AUC | Verdict | Lesson |
|---|---|---|---|---|---|---|---|
| E1 | MLP on 64×64 pixels | 85.1% | 79.7% | 0.697 | 0.891 | baseline | high bias: no notion of 2D structure |
| E2 | CNN, trained on Photo/Text/Schematics only | 99.7% | 75.3% | 0.688 | 0.872 | failure | 84% of paintings called photo: a model only learns distinctions present in its data |
| E3 | same CNN, all sources, no regularization | 99.9% | 90.8% | 0.831 | 0.960 | improvement | overfitting: val loss min at epoch 3 (0.23), ~0.6 at epoch 25 |
| E4 | + augmentation, BN, L2 1e-4, GAP, dropout 0.4, early stopping | 89.2% | 89.3% | 0.808 | 0.952 | failure | gap closed but bias up (over-regularized) |
| E4b-1 | dropout 0.2, L2 1e-5 | 86.8% | 86.2% | 0.776 | 0.937 | failure | early stopping fired at epoch 9 on an oscillating val loss |
| E4b-2 | dropout 0, L2 1e-5 | 84.0% | 84.0% | 0.736 | 0.915 | failure | even earlier stop: dropout also stabilizes training |
| E4b-3 | dropout 0.4, L2 0 | 91.9% | 91.5% | 0.850 | 0.969 | improvement | L2 was over-constraining the model |
| E4c | E4b-3 + ReduceLROnPlateau, patience 10 | 93.4% | 91.6% | 0.861 | 0.978 | improvement | stable training; best from-scratch CNN |
| E5 | MobileNetV2 (ImageNet), frozen, 160 px | 97.6% | 96.9% | 0.946 | 0.995 | improvement | transfer learning: low bias and low variance |
| E6 | E5 + fine-tune last 40 layers, lr 1e-5 | 98.3% | 97.9% | 0.963 | 0.998 | best | best part-1 model |

**E6 on the part-1 test set (used once):** accuracy 97.9%, precision 96.2%, recall 96.2%, F1 0.962, AUC 0.997
(threshold 0.82 chosen on validation). **Grayscale stress test:** photo recall 96.2% → 91.9% when test photos are
converted to black and white. **Error gallery:** the photos missed with the most confidence are old, sepia or
black-and-white prints, and several "errors" are folder-label errors (photos filed as Schematics or Painting).

## 4. Engineering incidents and fixes

| # | When | Symptom | Cause | Fix |
|---|---|---|---|---|
| 1 | first CNN run | `Autotuning failed ... No valid config found` | Keras 3 compiles with XLA, whose convolution autotuner needs scratch memory the 2 GB GPU lacks | `jit_compile=False` |
| 2 | first full run, E2 | `ResourceExhaustedError` (OOM) after E1 | TF can't release GPU memory between models in one process (fragmentation); async allocator unsupported on the vGPU | **one process per training** (`python -m leyenda.train <spec>`); the notebook kernel stays on CPU |
| 3 | dry run | 112 labels vs. 128 predictions | disk cache named only `val_160` was reused with other images | cache name keyed on a hash of the exact image list |
| 4 | E4c, attempt 1 | run lost at epoch 13 when the session closed | no checkpoints; process tied to the session | **atomic checkpoints** every epoch (`last.keras`, `best.keras`, `state.json`); resume with `fit(initial_epoch=...)`; tested by killing runs on purpose |
| 5 | checkpoint test | resumed backup unreadable | Keras `BackupAndRestore` writes in place; a kill mid-write corrupts it | write to a temporary file, then atomic rename |
| 6 | part 2, V1 attempt 1 | TF decoding error at epoch 1 | `painting_02662.jpg` is a **BMP file named .jpg**: PIL opens it, TensorFlow can't | the audit also checks every file with TensorFlow's decoder (`tf_decodable`); `clean_index` removes failures |
| 7 | part 2, background run | notebook execution stopped when the session ended | `setsid nohup` processes still belong to the session's process group | background jobs started with `systemd-run --user` (outside the session) |

## 7. Target: 99%, then 100% (2026-10-09)

The team asked for 99%, then for 100%. Analysis of what that requires:

- V1 makes **88 errors on 6,045 validation images**. 99% = at most 60 errors; 100% = 0.
- **Integrity rule:** validation and test labels are never edited, and no misclassified image is ever removed to
  raise the score. Relabeling the archive is out of scope (a separate project, decided by the team). Every
  remaining error is reported with its cause instead.

## 8. Error analysis of V1 (88 validation errors, visual review of every image)

Stored image by image in `reports/d1_v1_error_analysis.csv`.

| Group | Count | Description | Model's fault? |
|---|---|---|---|
| A | 40 | paintings accepted as photos: realistic landscapes and scenes, Magritte-style realism, digital art, but also some clearly painted styles | yes: the main weakness |
| B | 23 | colour photos missed: product shots on plain backgrounds, close-ups, graphic or dark scenes; most with P(photo) 0.2–0.45 | yes |
| C | 6 | old black-and-white or sepia photos missed with P(photo) ≈ 0 | yes: the colour shortcut |
| D | 4 | diagrams accepted as photos: colour-gradient plots, 3D renders | yes |
| E | 7 | folder label looks wrong: aerial/satellite photos and product photos filed in Schematics, photographed objects filed in Painting | **no** |
| F | 8 | ambiguous by definition: scientific figures and collages *made of photos* | **undefined**: TouNum must decide whether a figure made of photos counts as a photo |

**Conclusions.**
1. About 15 of the 88 errors (E + F) are not model errors: measured accuracy can't reach 100% against these
   folder labels. The ceiling is ≈ 99.7–99.8% on this validation set.
2. About 75% of the errors (A + B) share one root cause: MobileNetV2's ImageNet features describe *what* is in
   the image, not *how it was made* (photographed or painted). It's also a small 2018 network used at 160 px
   because of the 2 GB GPU.
3. Main lever chosen: **frozen foundation-model features** (CLIP, trained on 400 M image–caption pairs, which
   name the medium: "oil painting of…", "photo of…", "diagram of…"), extracted once in inference mode (fits the
   2 GB GPU), then small classifiers trained on top. Plus ensembles, test-time augmentation and vintage-photo
   augmentation for group C.
